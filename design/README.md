# design

The source both Flaunt frontends are generated from, plus the multi-artboard
design canvas they came out of.

It lives in this repo rather than in either frontend because it feeds **both**:
one source means `flaunt.network` and `bms.flaunt.network` cannot drift into
looking like two different products.

| File | What it is |
|---|---|
| `flaunt-walkthrough.html` | **The source.** One hash-routed page containing every screen of both apps, plus the BMS Cognito sign-in. Edit this. |
| `build-site.mjs` | Emits the two deployable bundles from it. |
| `*.dc.html`, `canvas.json` | The 14-artboard design canvas — the static mockups the walkthrough was built from. Reference, not part of the build. |

## Building

```bash
AWS_PROFILE=cloudmeter node build-site.mjs
```

Writes `../../Flaunt-PORTAL/public/index.html` and `../../Flaunt-BMS/public/index.html`.
Commit and push those repos to deploy them — pushing to `main` runs their workflow.

The script does three things per bundle: sets `APP` so each host serves only its
own screens (portal refuses `#/bms/*`, BMS refuses everything else), injects
`noindex` and a preview banner, and stamps the BMS build with the Cognito app
client id read from `FlauntBmsAuthStackProd`'s outputs.

**Deploy the auth stack before building**, or the BMS bundle keeps a placeholder
client id and nobody can sign in. It fails closed and says so on the page rather
than falling open, but it is a wasted round trip.

## What is not tracked

`flaunt-ui-prototype.html` is gitignored: ~2.6MB, almost all of it embedded
canvas-editor code, regenerated by re-seeding from the `.dc.html` artboards.
